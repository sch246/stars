# 星罗 core —— 关系的编辑器

> 状态:M0(L0)。这是重构的新内核,与旧的 `src/`、`webapp/`、`media/` 并行存在,互不影响。

## 目标

星罗是**关系的编辑器与维护工具**,不是文本编辑器,也不是图可视化玩具。

- 数据是**挂在文件上的关系层**:节点指向仓库里的文件,正文留在文件里。
- **内核是本体**:库 + CLI,人和 AI 调同一套接口。UI(查看器、VS Code 插件)只是视图。
- 重点不是"建立关系",而是**让关系可维护**:查询、校验、批量变更、审阅。
- 先搓一个宇宙,让一切从里面长出来;每一步都必须能亲眼看到。

## 数据模型(内核只有这些)

- **节点**:`id`(稳定、可读)、`label`、任意 `key=value` 属性。常用属性:`type`、`summary`、`file`、`status`、`seen`(写说明时文件的版本,见「过期检测」)。
- **边**:`(from, type, to)` 三元组唯一确定,可带属性。没有边 id。
- **边类型的性质**由"模式节点"声明:`symmetric`(无向)、`acyclic`(不成环)、`single-parent`(至多一个入边)。
- **n 元关系 / 区域 / tag** 不进内核:用"中心节点 + 成员边"表达,查看器可把中心节点渲染成区域。两种表示可无损互转。
- **模式节点**:id 以 `~` 开头。`~dependsOn kind=edgeType`、`~module kind=nodeType color=#bd00ff`……
  类型本身就是宇宙里的节点,所以改类型定义不需要改代码(这是 L2 自描述的地基)。
  视图(`~view/…`)、函数(`~fn/…`)、保存的查询(`~query/…`,见「查询」)也都是这样的节点。
- **`contains` 是什么意思由视图决定**:文件层级只是其中一种视图(`scan` / 实时同步铺的是"目录包含文件"),
  "模块包含文件""主题包含概念"一样可以用 `contains`,视图规则(`expand.relation`、`relations.contains`)决定怎么画。
  内核只在一处区分:文件同步只把**两头都是文件/目录节点**的 `contains` 当作文件系统的结构,别的 `contains` 和依赖、描述一样是你的关系,
  文件没了也不会跟着删。
  创世文件里的 `~contains` 只声明了 `acyclic`(不成环),**没有** `single-parent`:一个节点可以同时在几个容器里(文件既在文件夹里,也属于某个模块)。
  视图的容器树(空间、展开、tag)每个节点只能有一个位置:和文件路径对得上的那条(目录包含文件)优先,不然取第一条;
  其余的 `contains` 画成**淡线**(带箭头,不是疆界),空间里照样汇总、照样伸出去,所以"它也属于那里"看得见。
  (以前建的宇宙自己的 `~contains` 里可能还写着 `single-parent=true`,不想要就 `stars set '~contains' --unset single-parent`。)

## 文本格式

```
stars 1

node auth "认证模块" type=module file=src/auth.ts summary="登录与会话"
node session "会话" type=module
node ~related "关联" kind=edgeType symmetric=true

auth -dependsOn-> session status=proposed
auth -related- session
```

- 一行一个事实,按 id 排序,同一个宇宙总是序列化成同一段文本(git diff 友好)。
- 对称类型写成 `-t-`,方向无关。
- 文件头可带 `rev=N`:这个文件已包含操作日志的前 N 条。日志是权威的提交记录,宇宙文件可以**延迟写入**;读取时(`Store.load`)会回放文件之后的日志,所以任何进程读到的都是最新、一致的宇宙。没有 `rev` 的旧文件不做任何回放。
- 限制:`#` 注释读入时会丢弃(请用 `summary`);id 不能含空白/引号、不能以 `#` 开头。
- `file` 路径相对于**宇宙文件所在目录**(或环境变量 `STARS_ROOT`)。

## 操作与日志

所有修改走 `apply(universe, op)`,返回**逆操作**。`Store.commit` 落盘并追加一行到 `<file>.log`
(时间、`author`、操作、逆操作),所以 `undo` 免费,将来的**回放**也免费。

**写锁**:几个进程可能同时写同一个宇宙(CLI、`serve --watch` 的监听器、查看器、脚本、agent 循环)。
`Store` 的每次写入("重新读盘 → 改 → 追加日志 → 写文件",`undo`、草稿的增删、整批应用也一样)整段持有 `<file>.lock`:
用 `O_EXCL` 建锁文件(里面记着 pid、主机、时间),别人占着就退避重试,10 秒还拿不到报错并说出是谁占着;
占着的进程死了(本机的看 pid 还在不在,别的机器上的看是否超过一分钟)就接手。同一进程里可以重入。
一次加锁 + 放锁约 30 µs。内存里的缓存以"文件签名 + 日志大小"为钥匙,所以别的进程延迟落盘(文件没变、日志变长)也会被认出来。

给 L3/L4 预留的四个钩子(现在都是空实现):
1. 写入统一入口,每个操作带 `author`(人 / AI 名字 / 将来的代码节点)。
2. 类型与规则是节点,不写死在代码里。
3. `Store.policy`:操作前的权限检查位置,现在恒为允许。
4. 安全模式:将来启动时可不加载任何代码节点。

## 视图 = 函数

画面不是数据的一部分,而是 `evaluateView(宇宙, 视图规格) -> 场景` 这个纯函数的结果(`src/view.ts`)。
规格是一组**有序规则**,第一条匹配的生效:

```jsonc
{
  "look": "galaxy",
  "select": { "withRelations": ["dependsOn"] },          // 显示哪些节点
  "size":  [{ "when": {"type":"dir"},  "attr": "size", "rollup": {"relation":"contains","op":"sum"}, "scale":"log" },
            { "when": {"type":"file"}, "attr": "size", "scale":"sqrt" },
            { "by": "degree" }],                          // 大小来自属性 / 沿关系汇总 / 度数
  "color": [{ "when": {"type":"dir"},  "by": "group", "relation": "contains", "level": 1 },   // 同一子树同色
            { "when": {"type":"file"}, "by": "attr:ext" }, { "by": "type" }],
  "style": [{ "when": {"type":"dir"}, "shape": "nebula" }, { "when": {"type":"module"}, "shape": "ringed" }],
  "relations": { "contains": { "mode": "orbit" }, "describes": { "mode": "faint" }, "*": { "mode": "line", "arrow": true } }
}
```

- **关系怎么画由视图决定**:`contains` 在 `galaxy` 里是轨道(子绕父转),在 `tree` 里是连线,在 `deps` 里被隐藏。
- **派生属性是规则**:目录大小 = 沿 `contains` 汇总子孙的 `size`;颜色可以继承祖先。
- 视图存放在宇宙里:`kind=view` 的节点,id 为 `~view/<名字>`,`spec` 属性是上面的 JSON;同名覆盖内置视图。改它,查看器立刻变化。
- CLI/AI 也能算视图:`stars views`、`stars view galaxy [--json]`。

## 容器、展开与边提升

文件夹不是特殊结构:`contains` 只是一条普通关系。任何有子节点的节点就是**容器**。
同一个容器,视图决定它以哪种身份出现 —— 关系 `R(x,y)` 的几种可视化在这里都用得上:

| 容器的身份 | 表现 | 视图 |
|---|---|---|
| **节点** | 容器本身是一个点,用连线连着它的成员(和别的节点平等地产生关系) | `tree`、`orbit` |
| **域** | 没有节点本体,只有一个包住成员的疆域;远看是一个小星系(粒子是内容的缩影),走近了是一个空间 | `galaxy`、`recent`、`arch` |
| **tag** | 没有节点本体,也不画疆域;成员身上带着它的 tag,可以点亮、参与高亮,同 tag 的成员轻轻聚拢 | `tags` |
| **中心节点** | 关系本身被"实体化"成一个节点,连着它涉及的所有元素(n 元关系) | 数据层面:给关系建一个节点即可 |

- **边提升**:容器收起时,内部的关系消失;跨容器的关系**提升**到容器上并汇总计数
  (`a/x.ts -dependsOn-> b/y.ts` ⇒ `a/ -dependsOn-> b/ ×2`)。提升的边是**派生**的(`lifted: true`),
  查看器里画成细点线并标 `×N`;面板里能看到"收起后的对外关系(含内部汇总)"。

### 空间(`layout: "spaces"`):两种进入方式,语义不同

域视图下每个容器的内部是一个**独立的空间**:自己的力学模拟,只受自己内部关系的约束,和外界没有引力往来
(所以不会出现"整棵树被拽成单向放射状"的样子)。从外面看,一个空间就是一个点/小星系。进入它有两种方式:

| 操作 | 含义 | 发生了什么 |
|---|---|---|
| **放大**(到容器几乎占据小半屏幕,`space.enterAt`,默认 0.42 × 屏幕短边)/ `⏎` / 面包屑 | **切换空间**,和切换路径一样 | 有来源和目的,所以画面是连续的:镜头从外层"钻进"容器,之后画面里只剩这个空间;缩小或 `⌫` 回到上一层 |
| **双击** / `E` | **显式地把不同层级放到一起** | 容器在原地展开成一个域,里面是它自己的空间(仍然独立模拟),外层的东西不动;再按一次收起,`0` 全部收起 |

- **视觉是一个区间,切换是一个临界点**。画面只由 ρ 决定 —— 容器在屏幕上的盘半径(在子空间里时,用子空间的范围按同一几何折算),
  以进入阈值 T 为单位。切换只在 ρ ≥ T(进入)和 ρ < 0.95T(退出)时发生 —— 只留 5% 防抖,放大一点进去、缩小一点就出来
  (滚轮约 2 格;以前退出要缩到 0.54T,得滚 6 格)。因为两边按同一个 ρ 画,切换前后是同一幅画面
  (实测滚轮逐级穿过切换点:切换那一步的画面变化和相邻两步一样大,没有跳变)。
- **小星系展开成里面的空间**(ρ 从 0.4T 到 T):收起的容器画成小星系,旋臂上的每颗粒子本来就对应一个后代(内核给缩影带上了 id)。
  放大时粒子从旋臂上的位置一路移到它对应节点的真实位置、由小点长成那颗节点(粒子渐隐、节点在同一处渐显),
  孙辈的粒子汇入它所在的子星系,星系核心的光晕渐隐,连线晚一点出现,标签展开过半才出现。所以全程每个东西只出现一次 ——
  以前是"星系的粒子"和"半透明的真实节点"叠在同一块地方,分不清谁是谁。ρ 从 0.6T 到 2.2T,外面的兄弟渐渐淡到 15%,4T 以后完全消失。
- 显式的进入/退出(⏎、按钮、⌫)是一次缩放动画,同样走这个连续的过渡。刚退出来时,那个容器会继续按 ρ 收拢回星系,
  即使指针已经不在它上面。
- 自动展开(旧版的"语义缩放")已经去掉:展开会让不同层级挤到一起,这只应该是用户主动的决定。
- 跨空间的关系:在空间里看不到外面的节点,但能看到"从这里通往外面"的关系 —— 屏幕边缘的**外部连线桩**,
  按(成员、关系类型、方向、外面的落点)汇总计数;面板里列出"通往空间外的关系"。
- **节点预算**(平面布局,`expand.maxNodes`,没写 `depth` 时默认 1500):一层一层往下展开,同一层先展开孩子少的,
  再展开就超出预算的保持收起(一个小星系)。上万个文件的仓库在 `orbit`/`tree` 里因此不会"爆炸"成一张没法看的图
  (实测 1.7 万节点:画面 1500 个节点、每帧 ~9ms,原来全部展开时每帧 ~100ms、布局半径 2 万多)。
  双击/`E` 手动展开不受预算约束;不在画面里的容器(比如 `tags` 视图隐藏的目录)是透明的,不会因为预算把内容藏起来。
  CLI:`stars view orbit --max-nodes 3000`。
- 容器大小沿 `contains` 汇总,所以展开/收起前后节点大小不变;归一化对全部入选节点统一做,不会跳变。
- `contains` 里有环时会在环上断开一条父链,保证每个节点都可达。

CLI:`stars view arch`(架构级,只展开一层、隐藏文件)、`stars view galaxy --depth 2`、`--expand a/,b/`。

### 内置视图
`galaxy`(默认,空间:放大切换、双击就地展开)· `recent`(空间,颜色 = 多久之前动过)· `tags`(文件夹作为 tag,不显示目录本体)·
`orbit`(全部展开,子绕父转)· `arch`(空间,只看目录与模块)· `deps`(只看语义关系)· `tree`(平面连线)

`tags` 视图的规格:`"tags": { "relation": "contains", "depth": 2 }` —— 每个节点带上它最近 2 层祖先作为 tag,
`select.hideTypes: ["dir"]` 让目录本体不出现。底部的 tag 栏可以点亮多个 tag,命中的节点高亮。
布局是按 tag 层级的**圆堆积**(`d3.pack`):顶层 tag 一团,团里按第二层再分小团,每个节点被拉向自己的锚点,
团上写着 tag 名(第二层的名字在团够大时才出现)。只把节点拉向"组心"是不够的 —— 初始位置随机时所有组心都在中间,
各组永远分不开(1.5 万个文件会变成一个均匀的圆盘)。

背景(远方的星系 / 只有星点 / 纯黑)在设置面板的「显示」里选,或按 `B` 切换(`bg` 命令),记在浏览器里。

### 同一份代码在两端运行
`model.ts` / `expr.ts` / `view.ts` / `query.ts` / `llf.ts` / `format.ts` / `textsync.ts` 只依赖标准库。`stars serve` 把它们去掉类型后以 JS 提供给浏览器(`/core/*.js`,
用 Node 的 `module.stripTypeScriptTypes`,这是实验性 API),所以展开、收起、切换视图完全在浏览器本地计算,
CLI 与查看器永远是同一套逻辑。

## 信号与"最近编辑"

宇宙文件本身不记录时间,但有两个来源,做成视图可引用的**信号**(`EvalOptions.signals`,id → 毫秒时间戳):

| 信号 | 来源 | 含义 |
|---|---|---|
| `touched` | 操作日志 | 这个节点(或连着它的边)最近一次被编辑 |
| `fileChanged` | git 最近提交时间;工作区里未提交的文件用 mtime | 节点指向的文件最近一次变动;目录取后代里最新的 |
| `stale` | 体检的 `stale` 规则 | 1 = 说明写于文件改动之前(见「过期检测」);表达式里直接写 `stale` |

(干净克隆下所有文件的 mtime 都是克隆时间,没有意义,所以 mtime 只用于"工作区里有未提交修改"的文件。)

视图规则里:`{"by":"recency","signal":"fileChanged","halfLifeDays":10,"from":"#2f3b6e","to":"#ffcf70"}`
让颜色随"多久之前动过"在冷→热之间渐变(每过一个半衰期,新鲜度减半);`size` 规则也可以用
`signal` + `recency`;`rollup: {relation:"contains", op:"max"}` 让容器取后代里最新的。内置视图 `recent` 就是这样的热力图:
大小是体量,颜色是新旧。视图仍是纯函数 —— 当前时间(`now`)和信号都是输入,所以测试里可以固定它们。

## 视图规则编辑器与接口

规格就是宇宙里一个 `kind=view` 的节点,所以**所有入口走同一条通道**(都带 `author`、写操作日志、可撤销):

- 查看器里的 **✎ 视图规则**:改 JSON,250ms 后实时预览(无效时给出具体问题),"保存到宇宙"/"另存"/"删除"。
- CLI:`stars view <名> --spec` 读,`stars view-set <名> --spec '<JSON>' | --from 文件` 写(先 `validateSpec`)。
- HTTP:`POST /api/op`(`{op, author}`),`GET /api/history`、`/api/state?commit=`。
- 直接改 `universe.stars`:`~view/<名>` 节点的 `spec` 属性。

**写接口的安全**:默认只监听 `127.0.0.1`;校验 `Host`(防 DNS 重绑定);写和读历史都要求页面里内嵌的
随机 token(每次启动不同),并拒绝跨源请求。`--host 0.0.0.0` 会警告。

### 自由度的阶梯(性能优先,不加沙箱)

| 层级 | 形式 | 状态 |
|---|---|---|
| a. 规则 JSON | 有序规则 + `when` 相等匹配 | ✅ |
| b. 表达式 | 规则字段里写 JS 表达式:`size[].expr`、`color[].expr`、`style[].expr`、`when`、`select.where` | ✅ 直接编译成原生函数 |
| d. 槽位接代码节点 | 表达式里 `fn.名字(...)` 调用宇宙里 `~fn/名字`(`kind=function`,`code` 是一个函数表达式);`stars fn-set` 创建,agent 可以随手生成/替换 | ✅ 进程内直接调用 |
| c. 自定义布局力 | 视图规格 `forces: ["~fn/名字"]`,函数节点每 tick 被调用 `(nodes, links, alpha, ctx)` | ✅ |
| d. 整体替换成函数 | `(node, ctx) => scene` 一个函数管一整个视图 | 未做 |

设计取舍:**视图是"第一遍搜寻"的工具,所以必须快,不能为了安全多绕一层。** 因此表达式和函数节点都被
`new Function` 编译成原生 JS,每条只编译一次,运行时按节点下标读列(类型化数组),不为每个节点建对象、不经过解释器、
不跨进程/Worker 来回序列化。10 万节点上,四条表达式(筛选 + 大小 + 颜色 + 样式)的编译约 0.5 秒,展开/收起仍是 ~12ms。
安全上**没有沙箱**:表达式与函数节点以页面/进程的全部权限运行。个人使用时这是对的取舍;如果以后要共享/导入别人的宇宙,
再加一个"默认不执行函数节点"的开关即可(函数节点本来就是显式的、可以被识别的节点)。
JSON 仍是规范形式:界面编辑它,AI 补丁它,CLI 校验它(`validateSpec` 会检查表达式语法与 `fn.x` 是否存在)。

#### 表达式里可用的东西
- 变量:`id label type degree depth children descendants`;任意属性名(全是数字的属性自动是数值列,如 `size`、`ext` 是字符串列);信号 `touched fileChanged`(毫秒时间戳,没有记录 = 0)。
- 函数:`log log1p log2 sqrt pow min max abs floor ceil round clamp(x,lo,hi) mix(#a,#b,t) hsl(h,s,l) hash(str) days(t) recent(t,半衰期天数) now`,以及 `fn.名字(...)`。
- 颜色表达式返回 `"#rrggbb"`,或 0..1 的数(配合规则里的 `from`/`to` 渐变);样式表达式返回形状名。

```bash
stars fn-set heat --code '(t, s) => log1p(s) * (days(t) < 7 ? 3 : 1)'
stars view-set hot --spec '{"select":{"where":"type == \"file\""},
  "size":[{"expr":"fn.heat(fileChanged, size)","range":[2,14]}],
  "color":[{"expr":"recent(fileChanged, 3)"}]}'
```

## 性能

视图是"第一遍搜寻",所以展开/收起必须是毫秒级。`evaluateView` 被拆成两步:

- `compileView(宇宙, 规格, 信号)`:算好**所有**节点的静态外观(大小、颜色、样式、汇总、深度、度数……)。内部用整数下标 +
  类型化数组 + CSR 邻接表,规则前提预编译,颜色查找记忆化。宇宙/规格/信号变了才重新编译。
- `fold(展开状态)`:只算"现在显示哪些"和边提升,是数组上的线性扫描,不碰任何节点的外观。

`node bench/view.bench.ts 100000`(10 万个文件、约 20 万条边)的实测:

| | 之前 | 现在 |
|---|---|---|
| 展开/收起一个目录 | ~2500 ms | **~16–22 ms** |
| 编译(仅数据变化时) | — | 0.3–0.6 s |
| 含 4 条表达式的视图,编译 / 折叠 | — | ~0.5 s / ~12 ms |

(测试环境:4 核云容器,Node 22。)度数现在是全图的静态值,所以展开/收起时节点大小不会跳变。

渲染侧的手段(查看器):发光用预渲染精灵图而非每帧建渐变;视口外不画;屏幕上小到看不清的节点降级成点,收起的星系
小于阈值不画粒子;边、星系粒子、背景星点按样式/颜色合批;域的凸包缓存并节流;标签规划节流。每帧 `fill` 调用从约 2.8 万降到几十次。
**诚实的说明**:开发环境只有软件渲染,测不出真实帧率,所以我只报了调用次数,没报 FPS;真机有 GPU 时应当明显更好,但没有实测。

## 审阅:接受/拒绝提议,把汇总边提升为真边

AI 用 `--proposed` 写入的边和节点(`link … --proposed`、`add … --proposed`,即 `attrs.status = proposed`)是"待确认"的;
「提议」级的页面(见「页面桥」)写的也都是。查看器里:

- **✓ 审阅**(带数量徽标,没有待确认的提议时按钮变淡):列出所有待确认的节点(`＋ 名字`)和边、**是谁在何时提议的**(从操作日志回溯;
  节点按 `#id` 记,边按 `from|type|to`),逐条 ✓ 接受 / ✗ 拒绝(删除;拒绝节点会连带它的边),
  或"全部接受/全部拒绝",还有"↶ 撤销上一步"。点一行跳到该节点。
- 节点详情里:待确认的节点在标题下有一行「待确认的节点 · 谁 · 何时 ✓ ✗」,待确认的边旁边也有 ✓ ✗。星图里待确认的节点带一圈黄色虚线(和提议的边一样)。
- CLI:`stars accept <from> <type> <to>` 确认边,`stars accept <id>` 确认节点;体检(`lint`)的 `proposed` 规则把两种都列出来。
- 收起的容器的"对外关系(含内部汇总)"里,每条汇总出来的边有"提升"按钮:在两个容器之间写一条**真实存在**的边
  (带一条说明由多少条内部关系汇总而来)。这是"从统计走向断言"的一步 —— 汇总是派生的,提升后才成为宇宙里的事实。

所有写入都走同一条通道(带 `author: viewer`,写日志,可撤销)。

## 图编辑:选择、关系、整理、剪贴板

和文件管理器一个习惯,几乎不用学。每个动作都回显成命令(控制台里看得到),写宇宙的都能撤销。

**选择**:单击 = 只选它;Ctrl/⌘ + 单击 = 加进 / 移出;Shift + 单击 = 移出。右键从**背景**拖 = 框选:不按 = 重选,
Ctrl = 追加(并集),Shift = 减去(差集),Ctrl + Shift = 反选(异或),拖的途中按 / 松键模式跟着变,框里实时显示结果。
就地展开的容器要整个圆都在框里才算(否则框一小块就选中了外面的大文件夹)。`selection` 是集合,`selected` 是其中的「主」节点
(侧栏详情、双击、E、跟随按它);多选时侧栏列出成员,不跟随镜头。空间模式下别的空间里选中的照样留着,可以跨空间多选。
命令:`select a b --add|--remove|--toggle`、`select --all`(Ctrl+A,画面里的)、`select --type 类型`、`select --inside`(容器里的全部,递归)。
右键单击 = 菜单(各节往 `menuProviders` 里挂项):进入 / 展开、选中里面的、选中同类、删除、连到…、移动 / 复制 / 引用到…、复制 / 剪切 / 粘贴。

**关系**:右键从**节点**拖到另一个节点 = 建关系,方向就是拖的方向。从选中里的节点拖 = 整个选中都连过去(多对一);
从没选中的节点拖到选中里的节点 = 连到整个选中(一对多);两头都是多个时每一对都连(菜单里写明 N × M 条)。
松手弹出类型菜单:最近用过的在前(存在浏览器里),打字过滤,回车选中;没有的类型回车就新建,顺手登记 `~类型 kind=edgeType`。
⇄ / Tab 反向。触控板上右键拖不便时用菜单里的「连到…」:接下来点哪个节点就连到哪个。
边可以点选(离线 5px 以内):侧栏里改类型、反转、删除(`relink from type to --type 新类型 --reverse`,属性跟着走,一步撤回;Del 删除)。
汇总边(「×5」)点开列出底下的每一条真实的边,可以逐条选、反转、删,或全部改类型。

**整理**(`arrange.ts`):拖节点时按着 Shift = **移动**、Ctrl/⌘ = **复制**、Alt(或 Ctrl+Shift)= **引用**(也放进那里),
不按 = 只是给它一个拉力(多选时同一空间里选中的都被拉向指针),只改布局不改数据。拖的是选中里的节点 = 整个选中一起;
画面上跟着指针的是一组影子(保持相对位置),目标绿圈能放、红圈不能并写明原因。放在哪:指着的容器(收起的星系、展开的疆界、概念节点);
指着文件 = 它所在的文件夹;空地 = 当前空间;顶上的路径栏 = 那一层。停在收起的容器上 0.7 秒它就地展开,可以接着往深处放。
- 移动 = 换上级:去掉从原来的容器来的那条容器关系(视图里它所在的那个),加一条从目标来的。**文件 / 文件夹真的在磁盘上搬**,
  id(= 路径)跟着改,它的所有关系一起走(`renameNodes`),文件夹里的东西一起改名;文件只能移进文件夹(想让它也出现在概念里用引用)。
- 复制 = 一份新的:连同容器里的东西(沿容器关系递归)一起复制,里面之间的边、指向外面的边一起复制,外面指向它的不复制
  (像复制文件:它引用别人照旧,没人引用副本)。文件 / 文件夹在磁盘上复制一份(同名就叫 `a-copy.ts`);概念里装着的文件不复制文件本身,副本照样装着原来那个。
- 引用 = 只加一条容器关系(一个节点可以在几个容器里),什么都不搬。宇宙里写了 `~contains single-parent=true` 的,引用会被拒绝并说明怎么放开。
- 放到它自己身上、放进它自己里面的东西,一律拒绝(选中里互相包含的只动最外层)。
- 执行在服务端(`fsops.ts`):写锁里先动磁盘、再提交图的操作,任何一步失败就把做过的倒回去;监听器同进程,同步做完,它晚到的事件只会对出「没变化」
  (另一个进程刚好在对账时被抢先改了名,这批对账作废,稍后整个重新对一遍)。日志那一条记下动过的文件(`LogEntry.fs`),
  撤销时先把文件倒回去(搬回原处,复制出来的删掉),再撤销图的操作;没法动磁盘的地方(比如别的工具直接调 `Store.undo`)撤销这一步会拒绝,而不是只撤图。
- CLI:`stars mv a b <容器>`(`--top` 移到顶层,`--from 原容器` 指明从哪个移出)、`stars cp …`、`stars ln …`;查看器里同名命令,只给容器 = 选中的。

**剪贴板**(左下角,只存在这个浏览器里,按项目目录分开):Ctrl+C / Ctrl+X 把选中的存成一条(同时写进系统剪贴板:一行一个 id,外加私有格式),
Ctrl+V 粘贴进选中的容器(选中的是文件、或者就是剪贴板里的东西 = 它所在的容器;没选 = 当前空间):复制的 = 复制,剪切的 = 移动
(之后这一条变成复制,id 换成移动后的),Ctrl+Shift+V = 引用。点一条 = 放到最上面(Ctrl+V 粘贴的就是它);★ 钉住 = 书签,不会被挤掉;
⌖ 跳过去(选中它们,必要时切空间);⟶ 把选中的连到它 —— 跨层级的关系、远处的书签都走这里。用的是浏览器的 copy / cut / paste 事件,
所以侧栏里选中的文字照常复制、输入框里照常粘贴。从外面粘贴进来:普通文本 = 一个笔记节点(`note/<时间>`,标签是第一行);
文件(截图等)= 存进目标文件夹。外面的文件拖进画布 = 存进指着的文件夹(不覆盖同名的,文件名里的空白换成 `-`,一步撤回会删掉);
指着概念之类不是文件夹的节点时,文件存进项目根,再让它也装着(`/api/upload`,`saveUploads`)。

## 类型的样式(L2):在图里改类型,所有视图立刻生效

类型本身就是宇宙里的模式节点(`~module`、`~dependsOn`),**样式就是它们的属性**:

| | 属性 |
|---|---|
| 节点类型(`kind=nodeType`) | `color`(#rrggbb)· `shape`(dot / star / nebula / ringed / pulsar)· `scale`(大小倍率) |
| 边类型(`kind=edgeType`) | `color` · `width`(线宽)· `arrow`(true / false)· `mode`(line / faint / hidden / orbit / region) |

视图取外观时的先后:**视图规则明确写了的 > 节点自己的同名属性 > 类型节点 > 内置默认**。具体是:

- 形状:规则 `style: [{ "by": "type" }]` = 节点的 `shape` → 类型节点的 `shape` → 内置默认(目录星云、文件恒星、模块带环、概念脉冲星)。
  内置视图都用它,所以改 `~module shape=…` 在 galaxy / recent / tags / orbit / arch / deps 里立刻看得见;规则里写死了 `shape` 的视图照规则来。
  视图没有任何形状规则管到的节点,类型节点写了形状也用它(以前一律恒星)。
- 颜色:`color: [{ "by": "type" }]` 早就取类型节点的 `color`;现在视图没有颜色规则管到的节点,也用节点自己 / 类型节点写的颜色(以前一律默认色)。
  galaxy 里文件按扩展名、目录按顶层分组上色,这些视图里改文件类型的颜色看不出来 —— 「类型」面板会直接说明「这个视图里颜色由规则 color[1] 决定」。
- 大小:按规则算出半径之后再乘 `scale`(节点自己的 > 类型节点的),所有视图都生效。
- 边:视图里**专门写了这种边**的规则(`relations.dependsOn`)写了的字段优先,其余字段取类型节点;只落到兜底规则 `*` 的边,类型节点盖过兜底。
  所以 `~dependsOn mode=faint` 在没专门规定 dependsOn 的视图里都变成淡线,`mode=hidden` 就是到处不画。

**在查看器里改**:左上「类型」下拉列出节点类型(这个视图里没有的调暗)和边类型;点名字是显示 / 隐藏,点 ✎ 展开编辑框:
颜色、形状(五个小图标)、大小滑条;边类型是颜色、线宽、箭头(默认 / 有 / 无)、画法(默认 / 实线 / 淡线 / 不画)。
拖滑条、选颜色时先在本地预览(改内存里的类型节点、重算视图),松手才写进宇宙(作者 viewer,能 undo);每一项旁边的「默认」去掉这一项。
侧栏里节点的类型名也能点(`file ✎`),直接打开它的编辑框。控制台里回显等价的命令,不弹出来挡住面板。

```bash
stars types                                                   # 节点类型、边类型:用量与样式
stars type-set module -a color=#bd00ff -a shape=pulsar -a scale=1.5
stars type-set dependsOn -a width=2 -a arrow=false -a mode=faint
stars type-set module --unset scale                           # 去掉一项
stars type-set flows -a kind=edgeType -a color=#33ffaa        # 还没有边用到的新边类型:写明 kind
```

类型节点不在就新建(`kind` 按"有没有边用这个类型"猜)。样式的检查和改法在 `styles.ts`,CLI、查看器、脚本用同一份。

## 过期检测:说明写于文件改动之前

关系挂在文件上,文件会变。节点的说明(`summary`)是对着某一版文件写的;文件改了,说明还对不对没人知道 —— 图会悄悄变旧。

- **记版本**:节点的 `seen` 属性 = 写说明时文件内容的哈希(前 12 位)。哈希就是 git 的 blob id(文本先统一成 LF,换行风格不同不算改动)。
  **写 `summary` 时自动记**(CLI 的 `add -s` / `set -s`、查看器和脚本经 `/api/op` 写的都算,只要节点指向一个文件、操作自己没碰 `seen`)。
  记的时候顺手把那一版存进 git 的对象库(`git hash-object -w`,和 `git add` 存内容是同一回事,只是不动暂存区),
  所以之后能直接 diff 出"写说明之后改了什么";不在 git 仓库里也能检测,只是看不到改动。
- **发现过期**:体检规则 `stale`(warn):`seen` 和文件现在的哈希对不上。哈希按 (大小, 修改时间, inode) 缓存,没改过的文件不重新读。
  监听器发现文件改了(或者查看器保存了文件),只要有节点对着它记了版本,就重新体检推给查看器 —— 改完代码,图上马上标出来。
  只看文件,不看目录(目录里随便改一处就算过期,太吵)。
- **处理**:说明要改 → 直接改 `summary`(自动重新记);说明不用改 → `stars stamp <id>`(查看器里「仍然有效」)记下现在的版本。
  `stars stamp --all` 给所有"有说明、还没记过版本"的节点记上(已经过期的不会被一笔勾销)。
- **看改动**:`stars stale --diff`、查看器节点详情里的「看改动」(`/api/seen-diff`):写说明时那一版 → 现在,统一 diff。
- AI 的用法:`stars stale --diff --json` 拿到"哪些说明可能过期、文件改了什么",改说明或 `stamp`。
- `stale` 也是一个信号,视图规则和查询里都能用(`"select": {"where": "stale"}`、`stars query stale`)。

## 查询:表达式、路径条件、保存的查询(动态区域)

不另造查询语言:查询就是视图规则里那套**表达式**(属性、`degree`、`depth`、`children`、信号、`fn.名字(...)`),再加几个**路径条件**:

| 写法 | 意思 |
|---|---|
| `from('auth', 'dependsOn')` | 从 auth 顺着 dependsOn 走得到当前节点(直接或间接;第三个参数限步数) |
| `to('auth', 'dependsOn')` | 当前节点顺着 dependsOn 走得到 auth(= 直接或间接依赖 auth 的) |
| `near('auth', 2)` | 和 auth 相距 2 步之内,不分方向(第三个参数限边类型) |
| `out('dependsOn')` / `into('dependsOn', 'x')` | 出边 / 入边的条数(可限另一端) |
| `query('名字')` | 在另一个保存的查询里 |

省略边类型 = 任何边;对称的边类型两个方向都算。结果按参数缓存(一次可达性搜索,O(节点+边)),所以对每个节点调用不贵。
例:`type == 'module' && to('auth', 'dependsOn') && !query('reviewed')`、`out('dependsOn') > 0 && into('dependsOn') == 0`(依赖链的起点)。
路径条件在视图规则里同样能用(比如 `select.where`)。

- **保存的查询** = 一个节点:`~query/<名字> kind=query expr=<表达式>`(可带 `summary`、`color`)。成员不存,每次随宇宙重新算 ——
  这就是**动态区域**:新加的模块满足条件就自动在里面。查询之间可以互相引用(循环引用会报出来)。
- CLI:`stars query <名字 | '表达式'>`、`stars query-set <名字> --expr '…'`、`stars queries`(各自的匹配数)。
- 查看器:过滤框以 `=` 开头就是表达式(写错了下面直接显示错误),「＋ 存为查询」;保存的查询列在过滤框下面一行,
  点一下点亮它的成员(别的调暗,收起的容器上显示"N 处匹配"),侧栏显示条件和成员,能「改条件」(放回过滤框,边改边看)、删除。
  节点详情里列出它在哪些查询里。命令:`region <名字>`、`query`、`queries`、`query-set`。

## 草稿:批量改动先预览,再整批应用

AI 或脚本一次改几十处时,一条条落进宇宙再一条条撤销太累。草稿把一批改动先放在旁边:

- **写进草稿**:任何写命令带 `--draft`(`stars --draft link a dependsOn b`、`stars scan --draft`),或者 `stars run --draft fix.js`
  (脚本里所有的写入都进草稿,脚本自己读到的是"应用之后"的样子)。草稿在 `<宇宙文件>.draft`(一行一条 `{t, author, op}`),
  不进操作日志、不动宇宙文件。每条写入先在"应用了草稿的宇宙"上试一遍,做不了(节点不存在……)当场报错,不进草稿。
  读命令带 `--draft` 看"应用之后"的样子(`stars --draft ls`);`stars --draft undo` 去掉草稿的最后一条。
- **看**:`stars draft` 列出每一条和"应用之后 +N 节点 ~N −N · 边 +N −N"。查看器顶上出现「草稿」条,点「预览」:
  画的是应用之后的宇宙,**新增绿圈、修改橙圈、删除红圈**,删掉的节点留在原位看得见(连同把它挂在容器里的那条边);
  侧栏逐条列出改动(点一条跳到它碰到的节点,✗ 去掉这一条),选中被改的节点能看到每个属性的旧 → 新。
  预览时实时更新照样进来(草稿叠在最新的宇宙上),脚本还在写草稿时也能看着它长。
- **应用**:`stars draft apply`(查看器里「应用」)把整批作为**一次提交**落进宇宙 —— 一次 `undo` 全部撤回。
  宇宙在写草稿之后变了、某几条现在做不了,就**一条也不落**,报出是哪几条,`stars draft drop <序号…>` 去掉它们再应用。
- **丢弃**:`stars draft drop`(整个)或 `drop 2 5`(某几条)。草稿不进日志,丢了就没了(查看器里丢整个会先问)。
- 服务端:快照里带着草稿,草稿文件变了推 `draft` 事件;`POST /api/draft {action: apply | drop | add}`。
  静态导出也能预览(不能应用)。

## 设置:宇宙参数与热量(⚙ 设置,`,`)

物理参数和显示开关在查看器里实时调,存在 `~/.config/stars/settings.llf`(所有项目共用,见下面的"设置与快捷键是 LLF 文件")。面板按用途分组:**显示**(背景、文件夹边界、跟随选中、
高亮选中、淡入淡出)、**运动**(热量、公转、斥力、引力、连线长度)、**手感**(拖动力、疆域张力、收缩余量、进入空间)、
**体积**(真实体积、映射、上下限)、**高级**(间隙、阻尼,默认折叠;折叠状态记在浏览器里)。改过默认值的项名字后面有个小点,
双击名字恢复这一项;`全部恢复默认`一键回去。面板上的每个改动都是一条命令(`param 名字 值`、`bg`、`bounds`),控制台里会回显:

| 参数 | 作用 |
|---|---|
| 保持热量(默认开)/ 热量 | 模拟始终保持一点温度(`alphaTarget`,默认 0.03),和拖动时一样是"活的":对变化立刻有反应,但温度低,不抖。关掉则静止后停算,省电 |
| 公转 | 保持热量时,空间里的成员绕空间中心缓慢公转(视图里 `contains` 的 `spin` 再乘这个倍率;galaxy 默认约每秒 3px)|
| 斥力 / 连线长度 / 引力 / 间隙 / 阻尼 | 力导向的各项倍率与常数,平面布局和空间布局都生效 |
| 拖动力(默认 0.2) | 拖动时把节点拉向指针的力度(1 = 原来的手感;默认取 1/5)。锁定拖动会持续施力,太大就会一直加速飞走 |
| 疆域张力(默认 0.8) | 就地展开的空间的一圈**软边界**:成员超出自然疆域 E0 越多,被拉回的力越大(负反馈)。它同时决定:①软边界有多硬 ②拖成员时整组能分到多少拖动力(越大越早跟着指针走) ③松手后回弹多快。0 = 关闭(拖动会把疆域撑大,松手也不还原)。和**真实体积**无关:那个开关只决定展开压不压、占用撑不撑大,不决定有没有疆界 |
| 收缩余量(默认 3) | 整组**最多**能收缩多少(上限):成员在自己的空间里最多伸到 `E0×(1+余量)`,其余成员最多缩到 `≈ 1/(1+余量)`。实际深度还受张力影响(张力越小缩得越深);0 = 不收缩。默认组合(张力 0.8 / 余量 3)实测峰值收缩约 55% |
| 进入空间 | 放大到容器占屏幕短边的多少比例时进入它;0 = 跟随视图(默认 0.42)|
| 淡入淡出(默认开) | 空间内外切换时的交叉淡入淡出;关掉则瞬间切换,没有任何过渡 |
| 展开形态(默认 铺开) | 就地展开的容器:压入 = 内容等比缩进容器盘、占用固定为盘;铺开 = 按原尺度铺开、占用随内容撑大。要看清就滚轮放大 |
| 体积半径(默认开) | 打开:字节数决定半径(目录仍按 contains 汇总子孙字节数)。关闭:用视图自己的 size 规则(内置星系视图 = 目录 log 5–17、文件 sqrt 1.8–9) |
| 体积映射(默认 sqrt) | 体积半径开启时,字节数 → 半径的曲线:sqrt(面积 ∝ 体积)/ log(更紧凑)/ linear(最直白) |
| 归一化(默认 合一) | 合一:目录和文件在同一个池里归一化,同样字节数得到同样半径;分开:各条规则各自归一化,各自用满区间 |
| 体积下限 / 体积上限 | 体积映射后的半径区间(默认 2–24;上限滑条可到 200) |
| 边界(默认开) | 文件夹的虚线边界与半透明底;关掉后只剩文字与交互,边界和底色全透明(设置 → 显示 → 文件夹边界 / `bounds` 命令,或视图规则 space.boundary=false) |
| 跟随选中(默认开) | 选中后镜头立刻锁定它:节点钉在屏幕中央,世界绕着它转。双击靠"原地双击"识别(见下),所以不需要等到第二次点击才移动镜头 |
| 高亮选中(默认开) | **全局**明暗:选中后其它节点变暗(空间里 ×0.3、平面里 ×0.2),豁免的是选中节点、它在自己空间里的邻居、以及它展开出来的整棵子树。关掉则一律不变暗 |

**体量 → 半径的映射**(视图的 size 规则,[view.ts:208-210](src/view.ts)):默认目录 = 沿 contains 汇总子孙字节数后取 log(区间 5–17),文件 = 字节数取 sqrt(区间 1.8–9);scaleValue 见 [view.ts:355](src/view.ts)。
打开"体积半径"后,目录和文件改用**同一套**公式(同一个 scale 与区间 [2,24];目录仍汇总子孙字节数);"归一化"选**合一**时它们真的共用一个池 —— 同样字节数的文件和目录半径才相同(分开时是各自的池,同一个字节数会因为两边最大值不同而得到不同半径)。
画出来的"盘面积 ∝ 半径²":sqrt 时面积 ∝ 字节数;log 时面积 ∝ (log 字节数)²,巨大的内容被强烈压缩。收起容器的盘半径 D = 半径 × BODY(4.2),斥力按 D 线性给。

**相机只有一份状态**,就是 `transform`(screen = world × k + transform);d3.zoom 只当输入设备。跟随不是"第二台相机",
而是**每帧把 transform 挪到让选中节点居中**这一件事:进入用 smoothstep 平滑,之后精确钉住,所以锁定后缩放、拖动都零抖动,
镜头速度也不再取决于"这一帧谁调用了几次相机"(旧的 `camOrigin()` 每被调用一次就缓动一次,是抖动的来源)。
节点的屏幕位置由 `screenOffset()` 沿"就地展开"的祖先逐层累积平移/缩放算出,和 `drawSpace` 的几何完全一致,
所以**打开的文件夹内部的文件夹/文件也照样跟随**。取消跟随或切换选中只改目标、不动 transform,于是就地解冻、没有跃迁。

**高亮选中**是**全局**的:不再只暗"和选中项同层"的内容 —— 选中展开的文件夹里的一个成员时,最外层的东西也会暗;选中展开的文件夹本身时,平级的其它展开文件夹里的内容也会暗(豁免集见参数表;选中项的子树整体保持明亮)。见 [22-filter.js](viewer/app/22-filter.js) 的 `hlSet()`。

**原地双击**:选中后镜头立刻锁定,没有"等到第二次点击才动"的延迟。双击靠"同一屏幕位置、500ms 内第二次点击"识别,
第二次点击(哪怕它落在看文件时展开到 600px 的详情面板上)在捕获阶段就拦下,动作一律作用在**第一次点击的目标**上 ——
所以镜头已经移动、或面板盖住了那个位置,双击也不会点空。单击照常只选中;点一下再按住拖不会误判(第二次按下移动超过 3px 候选就作废,拖动照常)。

**就地展开的星系是"整组",疆域是软的**:容器盘的显示大小始终等于收起时的盘(内容按当前疆域等比缩放,`scOf` 动态适配),所以虚线边界**永远不会被撑大**、不会和外面重叠。拖动里面的成员时,他可以在自己的空间里一直伸到 `E0×(1+收缩余量)`,其余成员跟着等比缩小 —— 这就是"收缩",拖动中**不阻止它**。整组受到的力就是**同一个力**的分配:成员的张力(超出 E0 越远越强,`over²` 起步、到 `E0×余量` 封顶为线性)按同一个收缩程度分给整组,所以**收缩和拉力从第一刻起同步增长**,没有"先缩、然后突然能拉"的阈值。这套力**和有没有鼠标完全无关**(拖动时只多了一根指向指针的弹簧),所以松手时力是连续的 —— 不会弹一下,节点只是被张力平滑地拉回 E0。疆域以内不受影响,成员可以自由摆放。实测(1400×860,`repo`,E0=177,默认张力 0.8 / 余量 3):慢慢拖 12 步时,超出量 15→58→132→217 与整组位移 0→1→7→31→61→…→225 同增(同步),收缩峰值 55%,虚线半径全程 65.8 不变;松手前后成员速度 26→13→7.8→4.7→3.1…(单调衰减,无突跳);直接位移一个成员 120px 也会自己收回;嵌套展开再拖内层成员不再发散。虚线疆界不再是拖动把手(点它仍旧选中那个文件夹;拖它 = 拖背景 = 平移镜头),拖动把手只有**真正的节点**(亮点,包括收起的小星系):要整组搬一个展开的文件夹,就拖它里面的一个成员。热量关着时拖动会临时给子空间**和它的父空间**升温(否则反作用力推不动父空间),松手后冷却。**进入某个空间后**,同样的疆域张力照样生效(成员拖太远会被拉回,退出时整组不会缩成一个点),但**不会**去推外层的容器 —— 你在里面看不见它,根空间(宇宙本身)也不设边界。实测(张力 0.8 / 余量 3)在 `repo` 里拖一个成员 500px:e 174→329 封顶、外层容器位置 75.68→75.69(不动),松手后 e 平滑回到 ~200;把张力关掉则会一路拖到 398。另外,锁定后**拖动别的元素或背景 = 脱离锁定并取消选定**(镜头就地解冻,可以自由平移/缩放);但**拖动锁定本体不脱离** —— 它始终钉在屏幕中心、世界绕着它转,像开飞船。

**按下、拖动都不改变温度与动力学**。斥力、引力、连线随温度缩放,而碰撞不随温度缩放 —— 温度一变平衡点就变,
以前表现为按住节点时整张图收缩、松开又胀回去,刚切换视图时(温度高)紧凑、冷下来以后几十秒里慢慢胀开。现在:
- 按下什么都不做;指针挪动超过 3px 才算拖动。
- 拖动只是**施加一个力**:每一帧都按"当前指针位置 vs 元素当前位置"重算一根弹簧(不钉住它),周围的节点通过平常的力去响应。所以指针停在一个方向不动,力也一直朝那边给 —— 锁定/相机跟着走时元素钉在屏幕中心、目标始终在它前方,就像开飞船一样持续加速;不锁定时相机不动,目标就是指针的世界位置,元素靠过去停住。
- 域之间的推力、公转、拖动的拉力都按温度缩放(以平时的热量为 1,封顶 8 倍),平衡点与温度无关。
- 唯一的例外:热量关着时模拟是停的,力推不动任何东西,这时拖动临时升到热量设定值,松手后冷却。

实测:按住 3 秒,温度不变,平均半径变化 ≤0.7%(以前 orbit / tree 是 −8% / −12%);拖动时温度全程不变,
节点停在离指针 2~10px 处(邻居把它往回拉的那一点);切换视图后几秒内就稳定。

只有这一帧画到的空间(当前空间 + 就地展开的)保持热量,看不见的空间冷却后停算。就地展开的子空间一直在动时,
只有当它的疆域半径变化超过 2px 才通知父空间让位 —— 否则父空间会被不停地重新加热、抖个不停。
实测(热量开):每帧位移 ~0.045px,帧间速度变化 ~0.0001px(不抖);关掉 4 秒后完全静止。

## 在查看器里看和改文件(侧栏就是编辑器)

像原版星罗:**点一下文件节点,侧栏上半是它的属性,下半就是它的内容**,不需要 VS Code(将来在 VS Code 插件里,同样的动作会打开它自己的编辑器)。

- **轻**:点一下就打开,所以只要开头 24 KB(`/api/file?head=`,切在最后一个换行处),此时是只读预览;
  点进编辑框或滚到底才载入全文、变成可编辑(保留光标与滚动位置)。超过 2 MB 的文本只预览开头,不可编辑;图片直接预览。
- **点别处就收起**:点空白处或别的节点,侧栏回到别的内容;有未保存的修改会**自动保存**。保存被拒(文件在你打开之后被别处改过)
  就把你的修改留着,底部提示"回去处理",回去后能选"载入磁盘版本"或"用我的覆盖"。也可以随时 `Ctrl/⌘+S`。
- **实时**:磁盘上的文件变了(实时同步的信号立刻触发,否则每 3 秒查一次修改时间):没改过就直接载入新版本,改过就提示冲突
  (磁盘上的新版本恰好就是你改成的样子,不算冲突)。原来是 CRLF 的文件保存后仍是 CRLF;宇宙自己的存储与 `.git` 只读。
- **脏是比出来的**(借鉴 dsh-file-viewer):不存"改过了"的标志,而是"当前文本 ≠ 基线"(打开 / 上次保存 / 载入磁盘版本时的内容,
  换行折成 LF 比)。改了再改回来就是干净的:`Ctrl+S` 不发请求,切走不自动保存,关页面也不拦你。服务端再拦一道:要写的内容和
  磁盘上一字不差就不写(不碰修改时间,也不算冲突)。
- **增量保存**:保存只传"改动的那一段 + 基线的哈希"(`core/src/textsync.ts`:去掉公共前缀和后缀,边界不劈开 emoji;
  53 位的 cyrb53 哈希加长度,两端一致)。服务端把磁盘内容同样折成 LF,哈希对得上才拼进去,对不上就是别处改过了(409)——
  按内容判断,不靠修改时间。168 KB 的文件末尾加一行,请求只有一百来字节;「用我的覆盖」才传整份。
- **增量重新载入**:反过来也一样。服务端记着每个文件最近给出去 / 存下来的几版(按内容哈希,每个文件 4 版,总共 32 MB,
  最久没用的先丢);查看器重新载入时带上手上那一版的哈希(`/api/file?since=`),服务端还记得那一版就只回改动的一段,
  查看器拼回去、再核对一次哈希(对不上就要整份)。1.4 MB 的文件别处改了一处,重新载入的响应约 300 字节。
  磁盘变了而你也有没保存的修改时,比较"磁盘上的新版本是不是恰好就是你改成的样子"也走这条路;同一版的冲突只提示一次,不反复要。
  (没做 VS Code 那种"本地编辑、只传界面"的路线:可编辑的文件 ≤ 2 MB、平时只轮询修改时间,值不得那套协议的复杂度。)
- **宽度**:拖侧栏左边缘调整,看文件时和平时各记各的,双击边缘恢复默认。
- `VS Code ↗` 是 `vscode://file/…` 链接,查看器和文件在同一台机器上时可用。

### 文件类型处理器:每类文件有自己的视图,原文页始终可用

侧栏下半按文件的种类显示(借鉴 sch246/dsh-file-viewer 的处理器注册表):每个处理器自己判断能不能接这个文件,
回答"默认"或"可用"(带优先级);选哪个:这次指定的 > 记住的(按扩展名)> 优先级最高的默认 > 原文。
不止一个视图时,侧栏头上显示「打开方式」分段按钮,旁边的「记住」= 以后这类扩展名都用它(记在浏览器里)。

|---|---|---|
| 原文 `text` | 所有文本(可用) | 上面说的轻量编辑器 |
| 图片 `image` | 图片(默认) | 点一下全屏看(Esc / 再点关) |
| 预览 `markdown` | `.md`(默认) | 零依赖的小渲染器:标题、列表(含任务、嵌套)、表格、代码块、引用、链接、图片,以及引用式链接(`[![CI][1]][2]` + `[1]: 地址`,README 的徽章多是这么写的;徽章是图片,不用跑脚本)。「渲染 HTML」开着时原始 HTML 也渲染,但先清理(只留排版用的标签和属性;去掉脚本、iframe、表单、事件属性、`javascript:`、`position:fixed`;id 加前缀免得和查看器撞名);关着则原样显示成文字。项目里的相对链接点了就在星图里打开那个文件,`#锚点` 滚过去 |
| 预览 `html` | `.html`(默认) | 沙箱 iframe(不同源,碰不到查看器和 token)。「脚本」开关;「实时」开着时跟着编辑器里没保存的改动走(像 VS Code 的 Live Preview),关着只显示保存了的版本、保存后刷新;项目里别的文件变了(`serve --watch` 的信号)也刷新;「新标签页 ↗」在沙箱里单独打开 |
| 表单 `form` | `.llf`、`.json` / `.jsonc`、`.toml`(默认;超过 256 KB 的 JSON 只是可用) | LLF:文件里的类型标签就是 schema,和设置面板同一套控件,`!list<T>` / `!map<T>` 可以增删项。JSON / TOML:按值的类型挑控件(开关、数字、颜色、多行文本……),每一项都能删,每个对象 / 列表 / 表都能加(分组标题上的「+」,旁边选新一项的类型,默认跟上一项一样)。三种都只改动到的那一段(见下面「表单的格式」),停手 0.6 秒自动保存 |
| 宇宙 `universe` | `.stars`(默认) | 节点、边按类型的概况;是别处的 `universe.stars` 就能「作为项目打开」 |
| 信息 `info` | 二进制、太大 | 大小,建议用 VS Code 打开 |

所有视图**共用同一份文本缓冲**:在表单里改、切到原文看,改动都在;保存、冲突检测、切走时自动保存都按这份缓冲来。
Markdown / HTML 预览有「并排编辑」:上面是原文编辑器,下面是预览,打字时预览跟着走。每个预览自己的开关(渲染 HTML、脚本、实时、并排)
只在这个文件开着时有效,新预览的默认值在设置 → 文件预览(`mdHtml` 默认开、`htmlScripts` 默认关、`htmlLive` 默认开);命令 `preview <html|scripts|live|split> [on|off|toggle]`、`preview reload`。

HTML 预览引用的相对资源(css / js / 图片 / 字体)从 `/preview/<预览 token>/<项目>/<路径>` 取:iframe 带不了请求头,所以 token 放在路径里,
页面里的相对路径自然落在同一个前缀下;实时模式渲染的是编辑器里的文本,插一个指向同一前缀的 `<base>`。**预览 token 和 `/api` 的 token 是两个**:
开了脚本的页面能从自己的地址读到预览 token,但它只能读项目里的文件,什么也写不了。HTML / SVG 的响应带
`Content-Security-Policy: sandbox …`(不含 allow-same-origin),就算在新标签页里直接打开也碰不到查看器;`.git` 不提供。
(`/api` 也拒绝 `Origin: null` 的请求 —— 沙箱里的页面发出的就是这种。)

侧栏头上的 **📌 固定**(`pin [on|off|toggle]`):固定了的文件不跟着选中走 —— 单击别的节点,上面的详情换,下面的文件不换;
双击 / `open` 照样打开别的文件;什么都没选时再按 Esc 取消固定。看文档时顺手浏览星图、或者让一个页面一直开着(见「页面桥」)都靠它。

命令:`open [id|文件路径] [--with 视图] [--remember|--forget] [--full]`(双击、回车打开文件都是它),`edit`(切到原文并把光标放进去)。

**双击也是命令**,按节点的种类查 `keys.llf` 的 `dblclick` 表(`$id` / `$path` / `$dir` 换成被双击的那个):
`container - expand $id`、`file - open $id`、`image - open $id --full`、`markdown` / `html` / `form` / `universe - open $id`、`node - select $id`;
某类没写就按 `file`。可以在设置 → 快捷键 → 双击里改,或 `dbl <种类> <命令…>` / `dbl reset`。
- 接口:`GET /api/file?path=`(`&head=N` 只要开头、`&stat=1` 只要大小与修改时间)、`POST /api/file {path, content, mtime}`、
  `GET /api/raw?path=&t=<token>`(图片;`<img>` 带不了请求头,所以 token 放在查询参数里)。路径限制在项目目录内。

浮动面板(项目、参数、审阅)点面板外面就关,平移和缩放不算;视图规则编辑器只在没有未保存的草稿时才这样关;时间线是一种模式,不受影响。

## 项目:一个文件夹一个宇宙,一个服务打开多个

`stars serve` 启动时监听一个宇宙(主项目),之后在查看器里按 `P`(或点左上角的项目名)打开**项目面板**:

- **已打开**:这个服务里正在开着的项目,点击切换。切换只是换一条事件流,其它项目的实时同步继续在后台跑。
- **最近**:打开过的目录(记在 `~/.config/stars/recent.json`,遵守 `XDG_CONFIG_HOME`),★ 表示里面有宇宙。
- **浏览文件夹**:服务端的目录树(在没显示器的机器上用反代访问时,浏览的是那台机器的磁盘)。
  有宇宙的目录点"打开";没有的,"在这里建立宇宙"会用创世文件建一个,并扫描这个目录(遵守 `.gitignore`)。

项目 id 是宇宙文件绝对路径的哈希(稳定),写在地址栏 `#view=…&p=…` 里,所以每个浏览器标签可以停在不同的项目上,
刷新不丢;服务重启后,带着 `#p=` 刷新会按浏览器记住的目录自动重新打开。接口上就是给所有请求加 `?p=<id>`
(`/events`、`/api/op`、`/api/undo`、`/api/history`、`/api/state`),加上 `GET /api/projects`、`GET /api/ls?dir=`、
`POST /api/open {dir, create}`、`POST /api/close {id}`。`serve --watch` 时每个打开的项目都会开自己的文件系统同步。

**关掉一个项目**:项目面板里「已打开」每行的 ✕,或 `project --close [目录]`(默认当前的)。只是不再打开它(停掉它的同步和事件流),
不删任何文件,以后还能从「最近」里再打开;主项目(启动服务时的那个)不能关。正看着它的页面(包括别的标签页)收到 `closed` 事件,回到主项目。

**刷新后回到原来的位置**:所在的空间、就地展开了哪些(经典布局下是手动展开 / 收起的容器),按「项目目录 + 视图」记在浏览器里,
刷新、换视图再换回来都还在;选中的节点不记(免得一刷新就打开文件)。

## 命令、控制台与快捷键

查看器里**每个操作都是一条命令**,写法和 CLI 一样(`名字 参数… -选项 值`)。按钮(HTML 上的 `data-cmd`)、
快捷键(键位表 `KEYMAP`:键 → 命令行)、控制台、命令面板都只是调用同一张命令表的不同入口:

- **控制台**(`` ` ``,或底栏的「控制台」):在底部拉出;Tab 补全命令名和参数(节点 id、视图名、面板名、参数名……),
  ↑↓ 翻历史(记在浏览器里),`help` 列出全部、`help <命令>` 看用法和绑定的键。
- **回显**:点按钮、按快捷键、在星图上点选或双击时,控制台里会灰显出等价的命令(`· panel timeline`、`· select src/a.ts`、
  `· expand src/`)。边用边学,也能直接拿去绑键或写进脚本。
- **命令面板**(Ctrl K):模糊搜索全部命令(中文标题、命令名、子序列都行),回车执行;还要参数的命令放进控制台接着敲。
- **快捷键速查**(`?`):由键位表生成,所以永远和实际一致。打字时(输入框、编辑器里)只认 Esc 和 Ctrl K。
- 命令返回 `false` 表示"此时不适用"(没选中东西时按 `E`、时间线没开时按 ←),这时按键不被吞掉,也不回显。

| 类别 | 命令 |
|---|---|
| 面板 | `panel <tools\|side\|types\|rules\|timeline\|review\|projects\|settings\|console\|keys> [on\|off\|toggle]` |
| 视图 | `view <名字\|序号>`、`filter [文字]`、`type <类型> [on\|off]`、`tag [id]`、`select [id]`、`cancel`、`fit`、`bg`、`bounds` |
| 空间 | `expand [id]`、`enter [id]`、`exit`、`jump [id]`、`collapse-all` |
| 文件 / 设置 | `open [id] [--with 视图] [--remember] [--full]`、`edit`、`save`;`param [名字] [值]`、`param reset [名字]`;`bind` / `unbind`、`dbl <种类> <命令…>` |
| 时间线 / 项目 / 审阅 | `timeline <prev\|next\|first\|now\|play\|scope\|more>`;`project [目录] [--create]`;`review <accept-all\|reject-all>` |
| 写宇宙(与 CLI 同名同参数,作者记为 viewer,可 `undo`) | `add`、`set`、`rm`、`link`、`unlink`、`accept`、`undo` |
| 读宇宙(在浏览器里算) | `show`、`nb`、`path`、`ls`、`log`、`lint`、`views` |

左上角的面板只留每分钟都用的东西:项目(点名字切换)、视图、过滤框(右边的「类型」按钮展开按类型筛选,隐藏了几类就显示 −N)、
一行状态(有错误/警告时才显示,点一下 = `lint`),以及一行四个入口:时间线(`T`)、审阅(`R`,带待审数)、视图规则、设置(`,`)。

写入走现有的 `POST /api/op` / `/api/undo`;读取用浏览器里的宇宙和 `query.ts`(和 CLI 是同一份代码)。
键位表在 `core/keys.llf`(默认)和 `~/.config/stars/keys.llf`(你的)里,改键就是改这个文件,或在设置面板的「快捷键」页里录键、
用 `bind <键> <命令…>` / `unbind <键>` / `bind reset`。

### 遥控:`stars ui <命令…>`

既然每个操作都是命令,CLI(和 AI)就能直接操纵打开着的查看器:`stars ui select core/src/view.ts`、`stars ui "panel timeline"`、
`stars ui param heatLevel 0.05`。命令发给看着这个宇宙的页面执行,**第一个回报的页面的输出交回 CLI**(`stars ui show x` 能直接打印),
命令出错时退出码为 1;不带参数时从标准输入逐行读(`#` 开头的行忽略),可以当脚本用;`--json` 每条命令打印一行 `{ok, out, data}`
(`data` 是命令给程序的结构化结果,比如 `nb` 的 `[{ id, depth }]`)。页面上会灰显一行 `⇢ 命令 ← 谁`,控制台没开时弹一个小提示。

实现:`stars serve` 启动时把 `{端口, token, pid, 宇宙文件}` 登记在 `~/.config/stars/servers/<端口>.json`(权限 600,关服务时删掉),
`stars ui` 据此找到服务(`--port` 指定 > 主项目是当前宇宙文件的 > 只有一个时就是它),`POST /api/ui` → 服务端用 SSE 的具名事件 `ui`
推给页面 → 页面执行后 `POST /api/ui-result` 回报 → 服务端把结果交回 CLI(最多等 4 秒)。

### 页面桥:`window.stars`(在页面里写 agent)

侧栏 HTML 预览里**开了脚本**的页面可以调星罗的命令 —— 写一个观察图谱、提出改动的 agent 页面,或者一个盯着选中节点的小面板,
都不用碰后台。实现见 `core/src/bridge.ts`(浏览器与 Node 共用)。

```html
<script type="module">
  const { level } = await stars.info();             // { path, project, level, selected, view }
  const g = await stars.graph();                    // { nodes, edges, proposals, n }:整个宇宙的快照
  stars.on('select', async (id) => {                // 也有 change(宇宙变了:{ n, ops } 或 { n, reset })、level
    const r = await stars.exec(`nb ${id} --depth 2`);   // { out, data }:out 给人看,data 给程序(nb → [{ id, depth }])
  });
  await stars.exec('link a dependsOn b');           // 「提议」级:落成 proposed,等你在审阅里确认
  await stars.store.set('key', { any: 'json' });    // 沙箱里没有 localStorage;按页面存在查看器这边
</script>
```

- **页面拿不到 token。** 唯一的出口是 `postMessage` 给查看器;查看器只认**当前挂着的那个 iframe** 发来的、带着**这次载入的暗号**
  (每次载入换一个)的消息,然后照常走 `exec(line, 'page')` —— 和控制台、快捷键、遥控同一个入口,多一道检查。暗号和 `window.stars`
  由查看器注入:实时模式插进 srcdoc,非实时模式由 `/preview/…?bridge=<暗号>` 在返回的 HTML 里插(放在 `<head>` 最前面,比页面自己的脚本先跑)。
- **按命令的作用分级**,级别是累加的:

  | 级别 | 能用的 |
  |---|---|
  | 关 `off` | 没有 `window.stars` |
  | 读 `read` | `show` `nb` `path` `ls` `log` `lint` `views` `help`、`graph()`、订阅、`store`、`pin`(固定自己) |
  | 界面 `ui` | 再加选中、镜头、视图、过滤、类型、展开、进出空间、打开文件、面板、预览开关、时间线 |
  | 提议 `propose` | 再加写命令,但 `add` / `link` 都落成 `status=proposed`;`set` / `rm` / `unlink` 只能动**自己提的、还没被确认的**;不能改 `status`、不能 `accept` / `undo` / `review` |
  | 写 `write` | 写命令直接生效(`rm` 不弹确认框;照样能 `undo`) |

  每个命令在注册时声明 `effect`(`read` / `ui` / `write`);**没声明的页面一律不能用** —— `param` `bind` `unbind` `dbl` `bg` `bounds`(个人设置)、
  `save`(写文件)、`project`(开项目、可能新建宇宙)、`connect`(改自己的级别)。以后加的命令默认也不给页面。
- 页面的写入在日志里的作者是 `page:<路径>`,审阅、`log`、时间线里都看得到是谁;页面做的界面操作和写入在控制台里灰显 `命令 ← page:<路径>`,
  被拒绝的跟一行 `✗ 原因`。页面自己的查询不回显,错误只交回页面。
- **授权**:预览栏上的「连接 关 / 读 / 界面 / 提议 / 写」(= `connect <级别>`,`connect default` 回到默认,`connect` 列出全部)。
  按「项目目录 → 页面路径」记在 `~/.config/stars/grants.llf`(和设置、快捷键同一套:LLF、409 合并、别处改了实时生效),**不在项目里** ——
  克隆来的仓库不能给自己开权限。没单独授权的页面用设置 → 文件预览 →「页面连接」(`pageBridge`,默认「读」)。单独授权过、不是「关」的页面
  打开时自动运行脚本。级别在「关」和其它之间切换时页面重新载入(要加上 / 去掉 `window.stars`),其它切换就地生效,页面收到 `level` 事件。
- **页面动界面时先固定自己**:侧栏跟着选中走,页面一旦选中别的节点就会把自己换掉,所以页面发来的界面类命令会先 📌 固定它;
  只用「读」的页面想一直开着(比如盯着你的选中),可以自己 `stars.exec('pin')`,或者你点 📌。
- 不连的地方:新标签页里打开的预览(没有父窗口)、Markdown 预览(不跑脚本)。实时模式下每次编辑都会重新载入页面(循环跟着重来),
  写长时间运行的页面时关掉「实时」;关掉侧栏页面就停了 —— 重活更适合放在后台(CLI / 将来的 MCP)。

### 脚本:在 JS 里调命令

一行一条命令的写法(控制台、快捷键、`stars ui` 的标准输入)很像 mcfunction:简单、能绑键,但没有变量、循环、条件。
所以同一套命令也能在 JS 里调,三个地方拿到的是**同一个形状**的 `stars` 对象:

| 在哪跑 | 怎么跑 | 命令在哪执行 | 权限 |
|---|---|---|---|
| 侧栏里的 HTML 页面 | 预览开了脚本 | 查看器(页面桥) | 页面的连接级别 |
| 查看器里的脚本 | `run tools/x.js [参数…]` | 查看器(隐藏的沙箱 iframe + 页面桥) | 同页面,按脚本路径授权:`connect propose tools/x.js` |
| Node 里的脚本 | `stars run tools/x.js [参数…]`(`.ts` 也行) | 内核命令直接读写宇宙文件;其余转给打开着的查看器(同 `stars ui`) | 不分级(就是你在终端里跑的程序) |

```js
// tools/link-tests.js —— export default 的函数拿到 (stars, args);也可以直接写顶层代码(全局有 stars、args)
export default async function (stars, args) {
  const { data: tests } = await stars.cmd.ls({ q: '.test.' });        // = exec('ls --q .test.'),data 是节点
  const ids = new Set((await stars.graph()).nodes.map((n) => n.id));
  for (const t of tests) {
    const src = t.id.replace('.test.', '.');
    if (ids.has(src)) await stars.cmd.link(t.id, 'tests', src, { proposed: true });   // = exec('link … --proposed')
  }
  return `看了 ${tests.length} 个测试文件`;
}
```

- **`stars.cmd.<命令>(位置参数…, { 选项 })`** 由 `core/src/cmdline.ts` 的 `cmdLine` 拼成一行再执行,和敲出来的完全一样(控制台里看得到):
  `true` → `--选项`,数组 → 重复,对象 → `--attr k=v`,驼峰的名字 → 连字符(`collapseAll` → `collapse-all`、`maxNodes` → `--max-nodes`)。
  不用操心引号。切词(`cmdTokenize`)和加引号(`cmdQuote`)也搬进了这个共享模块,查看器、CLI、脚本只有一份。
- 其余:`exec(一行)`、`ui(一行)`(Node 里强制交给查看器)、`graph()`、`info()`、`on('change' | 'select' | 'level', f)`(Node 里只有 `change`,盯着操作日志)、
  `print(…)`、`store`(按脚本 / 页面存的小数据;Node 里在 `~/.config/stars/script-store/`)、`args`、`exit()`。
- **写完马上读得到**:查看器里的写命令要等这条操作经事件流应用回来才算完成,所以 `await stars.cmd.add(…)` 之后 `graph()` / `show` 就能看到它。
- 查看器里的脚本:`console.log` 转到控制台(`[x.js] …`);跑完了没订阅事件就关掉,订阅了就一直听着(`run` 不带参数列出、`stop [路径]` 停掉、
  脚本里 `stars.exit()`);再 `run` 同一个脚本会先停掉旧的;切换项目时全部停掉。它们和页面一样不能用 `run` / `stop` / `connect` 这类命令。
- Node 里的内核命令(`core/src/commands.ts`)是从 CLI 里抽出来的:CLI 的 `add` / `link` / `ls` / `show` / `nb` / `path` / `lint` / `log` / `views` / `view` /
  `view-set` / `fn-set` / `scan` / `undo` 都走它,返回 `{ out, data }`(`--json` 打印 `data`),脚本里的 `exec` 在进程内直接调,不另起进程。
  `stars run` 的脚本名之后的参数原样交给脚本,不当成 stars 的选项。

### 脚本节点与 agent 循环(L4)

简单的事在控制台里一行命令;复杂的写成**脚本节点**,存在宇宙里,手动跑,或者让它按触发自己跑。

```
~script/<名字> kind=script  code="<JS>"(代码在节点里)| file=tools/x.js(指向项目里的文件)
               on="change, file:src/**, stale, start"  every=10m
               draft=true · enabled=false · timeout=2m · debounce=1.5s · record=always · summary=…
```

- **写法**和 `stars run` 的脚本一样:`export default async (stars, args) => {…}`,或者直接写顶层代码(全局有 `stars`、`args`)。
  多了 `stars.trigger`:这次为什么跑 —— `{ kind: 'manual' | 'change' | 'file' | 'stale' | 'every' | 'start', paths?, ids?, ops?, by? }`
  (文件触发带上变了的路径,change 带上别人写的那几条操作,stale 带上新过期的节点)。
- **手动跑**:`stars run ~script/<名字> [参数…]`(当前进程里跑)· 查看器里选中脚本节点点 ▶,或者日志页「脚本」一栏的 ▶ · 控制台 `script-run <名字>`
  (这两个在服务端起子进程跑,和触发的一样)。
- **触发**:`stars serve` 给每个打开的项目都开着触发循环(`--no-agent` 关掉);不开查看器时用 `stars agent [--watch]`。
  - `change`:宇宙变了 —— 不算这个脚本自己写的、不算运行记录、不算改脚本节点本身,所以不会自己触发自己。
  - `file` / `file:<通配>`:项目里的文件变了(`**` 跨目录,`*` 不跨;以 `/` 结尾 = 这个目录下的全部)。内容改了要开着监听(`serve --watch`、`agent --watch`);
    新增、删除、改名由文件同步写进宇宙,也算。
  - `stale`:有说明新过期了(第一次体检看到的过期也算)。`start`:循环启动时跑一次。`every=10m`:定时,最短 5 秒。
  - 同一个脚本的几次触发攒一下(`debounce`,默认 1.5 秒)合并成一次;正在跑的时候又触发了,跑完再跑一次;同时最多跑两个脚本。
  - 每次运行是一个子进程:崩了、死循环了都不连累服务;超过 `timeout`(默认 2 分钟)就杀掉,记为超时。
  - `enabled=false` 停用触发(手动照样能跑);`draft=true` 把写入放进草稿,跑完在图上预览,再整批应用或丢弃(见「草稿」)。
- **运行记录**:每次运行追加一行到 `<宇宙文件>.runs`(时间、触发、耗时、状态、输出的最后 4000 字、写了几处、草稿加了几条;只留最近 2000 条);
  节点 `~run/<名字>`(`kind=run`,作者 `agent`)记**最近一次有事的运行** —— 写了东西、出错、超时、状态变了才更新(`record=always` 每次都更新),
  所以每 5 分钟检查一次、通常什么也不做的脚本不会把操作日志刷满。查看器的脚本面板列出最近几次运行,点开看输出。
- **在查看器里**:选中 `~script/<名字>`(日志页的「脚本」一栏点名字,或 `select ~script/<名字>`)—— 侧栏是 ▶ 运行、停用 / 启用触发、写进草稿的开关、
  `on` / `every` 两个输入框(回车保存,写错了当场说哪里错)、代码框(`Ctrl/⌘ + Enter` 保存并运行;指向文件的脚本,侧栏下半就是那个文件)、最近运行。
  触发跑完会提示一下(手动跑的结果在控制台里)。

```bash
stars script-set 补说明 --ref tools/describe.mjs -a on=stale -a draft=true -s 文件改了就重写说明,进草稿等我看
stars script-set 统计 -a every=1h --code 'export default async (stars) => { const g = await stars.graph(); stars.print(g.nodes.length) }'
stars scripts                      # 触发、最近一次运行
stars run ~script/统计             # 手动跑
stars agent --watch                # 没开查看器时在后台按触发跑
```

和查看器里的 `run tools/x.js`(浏览器的沙箱 iframe 里跑、按页面授权)不同,脚本节点在服务端的 Node 里跑,和 `stars run` 一样不分级。
脚本节点的定义与触发的写法在 `scriptnode.ts`(浏览器也用它说明触发、指出写错的地方),运行记录在 `runlog.ts`,跑和循环在 `agent.ts`。

## 设置与快捷键是 LLF 文件:配置即界面

设置和快捷键都是 [LLF](https://github.com/sch246/llf-format) 文件,设置面板就是这两个文件的表单,原文随时可以切过去改:

- **默认值**:`core/settings.llf`、`core/keys.llf`。它们带类型标签,本身就是表单的 schema:结构与默认值来自文件,
  控件来自标签(`!bool` 开关、`!range(最小,最大,步长[,最小值时显示的文字])` 滑条、`!choice(值=显示名,…)` 分段按钮、`!color`……,
  不认识的标签退回文本框),每项上方紧挨的注释第一行是名字、其余是提示,顶层的字典是分组(`!folded` = 默认折叠)。
  参数和泛型按 llf-format 的标签表达式约定(EXTENSIONS §4)解释:`llfParseTagExpr` 把 `range(0,1,0.01)` 拆成 `{ name, types, args }`,格式本身不变。
- **你的修改**:`~/.config/stars/settings.llf`、`keys.llf`(遵守 `XDG_CONFIG_HOME`),**只记改过的项**,结构与默认相同;
  快捷键里同名的键覆盖默认,写成 `_` 表示取消这个键。表单上把一项改回默认值,就从文件里删掉它(删空了的分组也删)。
- **写回只动那一段**:表单的每次改动是一个按路径的操作(`llfSetString` / `llfDelete`),注释、顺序、排版都不动;
  连续的改动合并成一次保存(`POST /api/config`,带读到时的修改时间,别处改过就 409:取最新版、把还没存上的操作重放上去再存)。
- **在别处改也立即生效**:服务端监听 `~/.config/stars`,文件变了就用 SSE 的具名事件 `config` 推给所有页面(编辑器里改、另一个标签页、
  `stars ui param …` 都一样)。原文页打字时停手 400ms 检查一次:合法就保存并生效;不合法只提示错在哪一行,不存半截的文件;
  不认识的项、不合法的值给警告并用默认值。
- **页面打开时就有**:服务端把默认文件和个人文件内嵌进页面(`<script type="application/json" id="stars-config">`),
  所以第一帧就用对的参数。静态导出只带默认值,个人设置存在看的人的浏览器里。
- **从旧版迁移**:以前存在浏览器里的设置(`stars.phys` / `stars.bg` / `stars.bounds`),在个人文件还不存在时自动搬进去一次。
- 第三个个人文件 `grants.llf`(页面连接的授权,见「页面桥」)走同一套读写、合并与推送,只是不在设置面板里显示成表单。

空注释行(只有 `#`)是分隔:它和它上面的注释不属于下面的条目(文件开头的说明不会变成第一项的名字,删第一项时也不会被带走)。

`core/src/llf.ts` 是 `llf.py` 的移植(浏览器与 Node 共用):`llfParse` / `llfStringify` / 帧流 / 标签 / 标签表达式,
外加**保留原文的文档模型**:`llfParseDoc` 给出每个值在原文里的位置和紧挨在上面的注释,`llfSetString` / `llfDelete` 只改目标那一段。
测试跑 llf-format 的全部向量(90 + 3 + 6 + 22 条,外加 29 条标签表达式向量)、往返 fuzz,以及"改完只动了目标区域"的编辑 fuzz。

项目里的 `.llf` 文件在侧栏里也显示成这种表单(见"文件类型处理器")。

### 表单的格式:LLF、JSON、TOML

三种格式都解析成同一种树(`kind` / `key` / `entries` / `items` / `value` / `comments`,也就是 LLF 文档模型的形状),
表单只认这棵树;每种格式提供"解析 / 按路径改值 / 删 / 加"四个函数。改动都只动那一段:缩进、键序、注释、引号风格都不变。

- **JSON**(`core/src/jsonc.ts`):认 JSON 加上 JSONC 的注释(`//`、`/* */`)和尾逗号(`tsconfig.json`、`.vscode/settings.json`)。
  改值按原来的类型写(数字不加引号;原来是 `null` 的,填的东西能当数字 / 开关读就照写,否则当字符串)。
  删一项连同属于它的注释和它那一行,删的是最后一项就去掉上一项多出来的逗号,删空了收成 `{}` / `[]`;
  加一项跟着已有的写法:各占一行就另起一行、同样的缩进,写在一行里就接在后面(`{"a":1}` 这种紧凑写法加进去也是紧凑的),尾逗号风格也保持。
- **TOML**(`core/src/toml.ts`):TOML 1.0 的全部写法(`[表]`、`[[数组表]]`、点号键、内联表、跨行带注释的数组、四种字符串、日期时间)。
  文件看成一个个"定义单元":一行键值、一段表(表头到下一个表头之前)、数组里的一项、内联表里的一个成员。
  删一项 = 删掉定义它和它下面所有东西的单元(删 `[servers]` 也删掉 `[servers.alpha]`;删数组表的一张连同它的子表);
  加一项按这张表是怎么来的放:表头定义的接在它最后一行键值后面,点号键带出来的接着用点号写(`owner.email = …`),
  只出现在别的表头里的(`[servers.alpha]` 里的 `servers`)补上它自己的表头,数组表加一段 `[[…]]`,内联表加进括号里。
  字符串尽量保持原来的引号(`'…'` 放不下单引号时才换成 `"…"`,多行的还是多行)。
- 两种都和 LLF 一样:**紧挨在一项上方的注释属于它**(表单里是提示,删的时候一起删),隔着空行的不属于任何一项。
- 测试:固定的例子逐行核对改动范围,另外各有 400 轮随机改动(随机生成的嵌套对象 / 表 / 数组表,随机删、加、改),
  每轮都检查结果还能解析、值和直接改对象一样。

## 在没有显示器的机器上使用

查看器是一个网页,服务跑在哪台机器都行。你的情况(Ubuntu 没有显示器、Windows 有),四种办法,按推荐度:

1. **SSH 隧道**(最简单,默认的安全设置不用动):在 Windows 上
   `ssh -L 4321:127.0.0.1:4321 你@ubuntu地址`,然后浏览器开 `http://localhost:4321`。Ubuntu 上正常运行 `node core/src/cli.ts serve`。
2. **反向代理**:`stars serve --allow-host stars.你的域名.com`(或环境变量 `STARS_ALLOW_HOSTS`,逗号分隔)告诉服务"这个域名是自己人"。
   nginx 要关掉对事件流的缓冲(服务已发 `X-Accel-Buffering: no` 并每 20 秒发一次保活):
   ```nginx
   location / {
     proxy_pass http://127.0.0.1:4321;
     proxy_http_version 1.1;
     proxy_set_header Host $host;
     proxy_buffering off;
     proxy_read_timeout 1h;
   }
   ```
   (`--host 0.0.0.0` 会监听所有网卡,局域网里的人都能访问,启动时会警告;写接口仍受 token 保护。)
3. **静态导出**:`stars export universe.html` 生成一个自包含的 HTML(查看器 + d3 + 视图内核 + 当前宇宙,约几百 KB,
   **零网络请求**),`scp` 到 Windows 双击打开。只读:能切视图、缩放展开、搜索、在编辑器里预览规则,但不能保存、没有时间线与审阅。
4. **在 Windows 上直接跑**:装 Node ≥ 22.18,`git clone` 同一个仓库,`node core/src/cli.ts serve`。宇宙文件在 git 里,
   分支、时间线、按事实合并都照常工作(`bash` 演示脚本需要 Git Bash/WSL)。

## 实时同步:文件系统 → 宇宙

`stars serve --watch`(或单独的 `stars watch`)让宇宙里的 `dir`/`file` 节点随磁盘实时变化,像 VS Code 的资源管理器。

**设计原则:事件只是线索,真相是重新读目录。** 监听器只负责告诉我们"哪些目录可能变了",`fssync.ts` 对这些目录
重新 `readdir`,与宇宙对账,算出一批操作。所以不依赖各平台事件语义的差异(创建/删除/改名/覆盖写),事件丢了、重复了、
乱序了,下次对账都会自愈。忽略规则不自己实现,直接问 `git check-ignore`,和 `.gitignore` 语义分毫不差。

据我所知 VS Code 的做法与此同源(原生递归监听、排除目录、事件合并与节流、风暴时放弃逐条而整体刷新、网络盘退化为轮询);
我们用零依赖的 Node 做了同样的取舍:

| | Windows / macOS | Linux |
|---|---|---|
| 监听 | 系统原生递归监听(一个句柄管整棵树) | 每个**宇宙里已知的、没被忽略的**目录一个 inotify 监听(不碰 node_modules) |
| 限制 | 几乎没有 | 达到 `fs.inotify.max_user_watches` 时降级为 10 秒一次的定时对账,不崩 |

事件处理:攒 80ms(最长 500ms)去重 → 一批脏目录 → 对账 → **一次提交**;脏目录超过 300 个(切分支、`npm install`)就做一次全量对账;
每 120 秒全量对账一次兜底;`.git/HEAD`/`index` 变了(提交、切分支)就刷新 git 派生的信号 —— 不用在仓库里装钩子。
新建目录时监听器是后加的,会补读一次堵住竞态。
宇宙自己的存储(宇宙文件本身、`*.stars.log`、原子写的 `.tmp`、签名 `.sig`、写锁 `.lock`、草稿 `.draft`、运行记录 `.runs`)不是居民:扫描和同步都跳过它们,
它们的写入也不会触发对账(否则每次提交都会改变"宇宙文件"节点的大小,自己喂自己)。别的 `.stars` 文件照常收录。

**对用户数据的态度**(文件被删 ≠ 关系应该消失):

| 磁盘上发生了 | 宇宙里 |
|---|---|
| 新建文件/目录(含整棵子树) | 新增节点 + `contains` 边,属性与 `scan` 一致 |
| 删除,节点只有文件/目录之间的 `contains` 边 | 移除节点 |
| 删除,节点带语义关系(依赖/描述/AI 提议…) | **保留**并标记 `missing=true`(lint 警告),文件回来自动取消 |
| 改名/移动(同名同大小;或同扩展名同大小;目录则看内容签名) | `renameNodes`:节点连同**所有关系**一起改名,归属目录跟着变;**有歧义就不猜**,当作一删一增 |
| 修改内容 | **不写宇宙**(否则 git diff 全是噪音)。大小与修改时间作为"实时信号"推给查看器,覆盖同名属性(`size`),所以节点大小立刻变化 |

### 增量传输
查看器连上后收一份完整快照,之后服务端只推:`ops`(新追加的日志条目,浏览器用同一份 `apply()` 在本地更新宇宙)、
`signals`(实时的大小/修改时间)、`issues`(节流 1.5s)。日志序号有缺口、`apply` 失败,浏览器会自己重连要一份新快照。
宇宙文件被外部改动(`git checkout`、手改)而日志没动时才推完整快照;Store 自己的延迟落盘靠一个旁路签名文件识别
(放在 `.git/` 里,不会被提交或参与合并),所以不会误判成外部修改。编译很贵时(大宇宙)查看器按上一次编译耗时自适应地合并更新。

### 实测(4 核云容器,Node 22)
| | 结果 |
|---|---|
| 浏览器端到端:新建文件 → 出现节点 | ~170 ms |
| 改名(关系保留) | ~170 ms |
| 修改内容 → 节点大小变化 | ~360 ms(宇宙文件无新增写入) |
| 2000 个文件一次落地 → 全部出现 | ~450 ms,只提交 2 次 |
| 3 万文件的宇宙:启动全量对账 | ~0.5 s |
| 3 万文件:新建 1 个文件(落进宇宙) | **73 ms**(优化前 1746 ms:每次同步重新解析 3.6 MB 并整份重写) |
| 空闲 | 0 CPU,内存 ~114 MB,监听数 = 目录数 |

`node bench/watch.bench.ts 30000` 可复现。演示:`AUTO=1 bash demo/live-fs.sh`。

## 历史、分叉与合并

回放的依据是 **git 里宇宙文件的提交图(DAG)**,不是一条线:`gitHistory` 取所有分支上改动过它的提交
(含合并提交的两个父节点)和分支名,`gitSnapshot` 还原任一提交时的宇宙,`diffUniverses` 给出与父提交的差异。
操作日志(`.log`)是线性的,只负责提交**之内**的细粒度(谁、何时、改了什么,以及撤销);它是只追加的,
所以 `*.stars.log merge=union`。

宇宙文件是排序后"一行一个事实",两个分支在同一处相邻插入时 git 的**文本**合并会冲突。所以提供了**按事实的三方合并**
(`merge.ts`):节点/边按身份合并,同一事实的**不同字段**各改各的能自动合并;只有"同一字段改成不同值"、
"一边删一边改"才算冲突(取 ours 并报告),"一边删节点、另一边给它连了边"会恢复节点。
`stars install-merge` 把它装成 git 合并驱动,并在 `.gitattributes` 里写上 `*.stars merge=stars` 与 `*.stars.log merge=union`
(之前漏了后一行:两个分支都改过宇宙时,合并必然在操作日志上冲突)。

查看器的 **⏱ 时间线**:画出分支与合并,点击任一提交回放那一刻的宇宙(新增节点有绿环 + 扩散动画,修改的是橙环,
顶部显示 +新增 ~修改 −删除),◀ ▶ / ← → 单步,▶ 沿主线播放,Esc 回到现在;有未提交修改时会多一个"工作区"。
回放时节点位置按 id 延续,所以能看到宇宙"长"出来。演示:`bash demo/history.sh`(生成一个有分叉与合并的仓库)。

**文件夹的历史**:宇宙文件是新建的(还没提交过)时,它自己没有历史,但仓库本身的历史可能很长。这时时间线自动改看所在文件夹的
git 历史(头部的按钮可以在"宇宙文件的历史"和"文件夹的历史"之间切换):提交图是文件夹自己的;某个提交时的宇宙由那时的文件树
现场长出来(`git ls-tree`,和 scan 同样的规则,宇宙自己的存储不算),再挂上现在的模式、视图、概念和两端都还在的语义关系。
单步回放时上一个提交的结果有缓存。

长而复杂的历史:
- 取的是本地分支、远程分支、标签与 HEAD 上**改动过宇宙文件**的提交,`--full-history --simplify-merges`
  保留真实的分叉与合并、去掉没动过它的合并;`--date-order` 让横轴是时间(并行的分支交错排在各自的泳道上)。
- 先载入最近 300 个,`更早 …` 每次翻倍往前载入(`/api/history?limit=`)。差异按提交的**真实第一父提交**算,不依赖窗口。
- 泳道布局:每条边沿自己的泳道走,只在分出、汇入时拐一下弯;泳道用完就回收。不会再有横跨整张图的斜线。
  顶部是日期刻度,分支名标在它最近一次动过宇宙文件的提交上(指向的提交没动过时往前找)。面板最多占 34% 屏高,超出滚动。
- 实测(合成仓库:517 个提交、52 个分支、67 个合并):打开 ~0.9 s,13 条泳道,横穿的斜线 0 条。

## 校验(lint)

`stars lint`,有 error 时退出码 1。规则在 `src/lint.ts` 的 `RULES` 里,一项一个函数:

| 规则 | 级别 | 说明 |
|---|---|---|
| `dangling-edge` | error | 边指向不存在的节点 |
| `cycle` | error | `acyclic=true` 的类型出现环 |
| `multiple-parents` | error | `single-parent=true` 的类型有多个上级 |
| `undeclared-edge-type` / `undeclared-node-type` | warn | 类型没有对应的模式节点 |
| `missing-file` | warn | `file` 指向的文件不存在 |
| `stale` | warn | 说明写于文件改动之前(`seen` 和文件现在的内容对不上,见「过期检测」) |
| `orphan` | info | 没有任何关系的节点 |
| `proposed` | info | 等待人确认的 AI 提议边 |
| `rule:<名字>` | 自定 | 宇宙里的自定义规则(见下) |
| `rule-error` | error | 自定义规则的表达式写错了(报在规则节点上) |

**自定义规则也是节点**:`~rule/<名字> kind=rule expr="<布尔表达式>" level=warn|error|info message="提示"`。
表达式和视图规则、保存的查询同一套(属性、`degree`、路径条件 `from / to / out / into`、`fn.名字`……),命中的每个节点报一条(一条规则最多列 500 个)。
查看器的「需要关注」、`stars lint`、服务端推的体检结果里都有。

```bash
stars rule-set 模块没说明 --expr "type == 'module' && !summary" -s 模块没有说明
stars rule-set 没人用 --expr "type == 'module' && into('dependsOn') == 0" -a level=info -s 没有别的东西依赖它
stars rules          # 列出规则和各自命中的数目
```

AI 建议用 `stars link ... --proposed --author <名字>` 写入;人用 `stars accept` 确认。

# 或手动:
node src/cli.ts init                         # 在当前目录建 universe.stars
node src/cli.ts scan .                       # 把仓库铺成 dir/file 节点
node src/cli.ts add auth "认证" -t module --ref src/auth.ts
node src/cli.ts link auth dependsOn session --proposed --author claude
node src/cli.ts stale --diff                  # 哪些说明写于文件改动之前,改了什么

## 已知限制 / 待决问题

- 一个节点在几个容器里时,空间视图里它只出现在一个容器里(见「数据模型」),在别的容器里只是一条淡线;
  "两个模块都包含这个文件"时选哪个当位置,取的是边的先后(两条都不是文件夹层级时)。
- 查看器是独立的小实现,**没有**复用旧 webapp 的渲染层(它绑定在旧 schema 上)。`rollup` 假定关系无环。
- 刷新后记得所在的空间和展开状态,但记在浏览器里(按项目目录 + 视图),换浏览器就没了;选中的节点不记。
- 浏览文件夹在 Windows 上换盘符要手输路径(如 `D:\`)。
- 回放以提交为粒度;提交之内的细粒度(操作日志)还没接进时间线。回放时看不到被删除的节点(只显示 −N)。
- 表达式/函数节点没有沙箱(有意为之,见"自由度的阶梯");自定义布局力(c 级)已支持(forces),整体替换视图的函数(d 级)尚未实现。
- 每次数据变化都会重新编译视图:10 万节点约 0.3–0.6 秒,更大规模需要增量编译(查看器已按耗时自适应合并更新)。
- 实时同步:`stars watch` 与 `stars serve`(不带 `--watch`)分属两个进程时,服务端每次文件变化要重新解析宇宙文件(3 万文件约 0.5 s),建议用 `serve --watch` 合并成一个进程;重命名识别只在同一批事件里配对,跨很长时间的"先删后建"会被当作删除+新增;日志在大批量落地时会变大(存了逆操作,2000 个文件约 0.6 MB)。
- 背景里的远方星系纯属装饰(固定种子,不可交互,`B` 可关);让它们代表真实的"别的宇宙"(= 别的已打开项目)是后话。
- Windows/macOS 的原生递归监听在本环境(Linux 容器)里没有实测过。
- `/core/*.js` 依赖 Node 的实验性 `stripTypeScriptTypes`,将来 API 变了需要换成构建步骤。
- 查询就是表达式(见「查询」),没有"返回路径/子图"的查询;点亮查询是调暗别的节点,没有给成员画一圈疆界(成员可能散在不同的空间里)。
- 过期检测只看节点指向的文件本身(目录、锚点 `#…` 之后的部分不细分);旧版本靠 git 对象库,被 `git gc` 清掉之后只能知道过期、看不到改了什么。
- 草稿只有一份(按宇宙文件),不进操作日志,丢了不能撤销;预览里被删的边(挂在容器上的除外)不画,只计数、在列表里列出。
  查看器里的写命令不进草稿(草稿来自 CLI / Node 脚本 / `/api/draft`)。
- JSON / TOML 表单不改值的类型(字符串改成数字、标量改成对象这类到原文里改);不认 JSON5(不带引号的键、单引号);
  TOML 内联表里用点号键带出来的子表不能在表单里加项。增量重新载入记的基线在服务端内存里,重启后第一次重新载入是整份。
- 脚本节点每次运行起一个子进程(启动约 0.1–0.2 秒),适合"几秒一次"以上的节奏;子进程里的脚本以你的权限运行,没有沙箱(L3 未做)。
  `file:` 触发要开着监听才认得出内容的改动;服务没开、`stars agent` 也没开的时候,触发不会补跑。
- 类型样式只覆盖颜色、形状、大小(边:颜色、线宽、箭头、画法);标签字体、图标这类还没有。视图里专门写了的规则优先,改类型节点在那些视图里看不出来(面板会说明)。
- 关系的批量建立:多对多现在是「每一对都连」,没有「一一对应」(选中没有顺序,配对有歧义);关系一多(某个节点几十条边、
  剪贴板里一组连到另一组)图会糊成一团,打算用前面说的 tag 式呈现或换视图来解决,还在想。
- id 里不能有空白,所以磁盘上名字带空格的文件当不了节点;复制、粘贴进来的文件改用 `-`(`a-copy.ts`、`my-note.txt`)。
  外面拖进来的只能是文件,文件夹拖不进来;一次最多 48 MB。撤销「复制文件」会删掉副本,哪怕之后改过它。
- 移动有几个上级的概念时,从视图里它所在的那个容器移出(CLI 要 `--from`);剪贴板、最近用过的关系类型存在浏览器里,换浏览器就没了。
- 页面桥的级别是按命令粗分的,不能细到"只能写某个区域"(那是 L3 的"用关系表达的权限");提议级"只能动自己的提议"靠操作日志里的作者(`page:<路径>`)判断。
  `store` 存在浏览器里(按项目目录 + 页面路径),换浏览器或换端口就没了。
